# 公式乱码修复 + 问答生成链路核查

> 触发：主人在问答里看到这样的答案 ——
>
> > 如果Δ**狓**→0时，Δ**狔**Δ**狓**无限趋近于某个定值…
> > `\[ \text{狔}' = \lim_{\Delta狓 \to 0} \frac{\Delta \text{狔}}{\Delta \text{狓}} ]`
>
> 并要求「问答环节要有大模型的参与」。

## 1. 结论速览

| 问题 | 结论 |
|---|---|
| 公式为什么乱码 | **不是模型的问题，是数据的问题**。教材 PDF 的字体没有正确的 ToUnicode 映射，数学斜体字母被抽成生僻汉字（`x`→`狓`、`y`→`狔`）。模型只是**照抄**上下文 |
| 改了什么 | 新增 `system/rag/text_cleanup.py`，在入库前修字形；全量重建索引 |
| 修了多少 | 27 本教材共修复 **57,522 处**；全库 591 万字符修复后**残留 0** |
| 检索指标受影响吗 | 同机同参数 A/B 对照：**基本持平**（各项波动 ≤1.5pt ≈ 1 道题，噪声范围内） |
| 大模型参与了吗 | **参与了**。教材原文与内容 JSON 里都没有 LaTeX，那段 `\lim \frac` 只有生成模型会写；实测 `llm_used=True` |

顺带修掉的两个真缺陷见 §7，其中一个是**评测脚本本身**的问题 —— 它一度让"100%"变成残缺样本上的假数字。

---

## 2. 根因

### 2.1 字形错映射

人教版 / 人教中图版电子教材 PDF 使用方正系列字体。**数学斜体字母在 PDF 里没有正确的
ToUnicode 映射**，抽取时被落成生僻汉字：

| 真实字符 | 抽出来的字符 | 码点 |
|---|---|---|
| `x` | 狓 | U+72D3 |
| `y` | 狔 | U+72D4 |
| `A` | 犃 | U+7283 |
| `f` | 犳 | U+72B3 |
| `R` | 犚 | U+729A |

实测规模（27 本教材，入库前统计，**不含分块重叠**）：

| 类别 | 处数 |
|---|---|
| 错映射字形（61 种：斜体字母 + √ ∥ \| + PUA 真符号 + 括号碎片） | 51,176 |
| 噪声（PUA 未映射部分 + 异体文字） | 6,346 |
| **合计** | **57,522** |

> 索引层面的扫描数字会更大（分块有重叠，同一段会重复计数）：修复前全库
> 5,916,166 字符里有 8,264 个 PUA 字符 + 4,134 处异体文字噪声，约占 0.21%。

**这个问题几乎只在数学册**：数学必修一单本就修复 12,300 处，而物理必修二只有 29 处
（物理册用的是可正常抽取的字母）。

### 2.2 PUA 里藏着真符号，不能当噪声删

这是修的过程中一个容易踩空的点。私用区字符看起来是"方框"，但高频的那几个**承载真实语义**，
删掉会掉信息：

| 码点 | 真实符号 | 教材原文判据 |
|---|---|---|
| U+E02F | `∀` | 「并用符号“[∀]”表示」（全称量词） |
| U+E01B | `⊂` | 「犪[⊂]β，犫[⊂]β，犪∩犫＝犘」 |
| U+E03C | `⇒` | 「犘（犅）＝犘（犃）[⇒]犘（犃犅）＝犘（犃）犘（犅）」 |
| U+E012 | `*` | 「犿，狀∈犖[*]」= N*（正整数集） |
| U+E011 | `-` | 「图１．１[-]１」；「ｕｎｉｔｖｅｃ[-]ｔｏｒ」 |
| U+E010 | `.` | 「１[.]１　空间向量及其运算」= 1.1 |
| U+E5C6 | 冗余 | 恒出现在换行后、且前文已有 `→`，删除 |

前 7 个占全部 PUA 的 94.6%；剩下的 24 个码点（约 450 处）确属纯噪声，删除。

### 2.3 为什么模型"修不好"

模型看到的是「参考材料」里已经被污染的原文。它**没有理由、也没有能力**把 `狓` 改回 `x` ——
照抄是理性的行为。**上下文干净，答案才可能干净。**

## 3. 映射表是怎么确定的（不是猜的）

最有力的一条判据来自人教 A 版数学选择性必修第三册原文：

> 通常用大写英文字母表示随机变量，例如**犡，犢，犣**；
> 用小写英文字母表示随机变量的取值，例如**狓，狔，狕**。

这一句同时锁死了 `犡=X 犢=Y 犣=Z` 与 `狓=x 狔=y 狕=z`。其余条目按字母序 + 公式语义
逐条验证，每条都在映射表里注明判据原文，例如：

- 「λ，μ∈**犚**」（实数集）→ `R`
- 「设**犻**，**犼**，**犽**是空间中三个两两垂直的向量」→ `i / j / k`
- 「仓库的长**犔**大于宽**犠**的４倍」→ `L / W`（决定性判据）
- 「在四边形犗犆犃犅中，犗犅**瓚**犆犃，所以犗犆犃犅是平行四边形」→ `∥`
- 「**狘**犘犉１**狘**＝狘犘犉２狘＝犪」= |PF₁|=|PF₂|=a → `|`

完整表见 `system/rag/text_cleanup.py::PDF_GLYPH_MAP`。

**小写 `o` 刻意不设映射** —— 它在任何教材里都没出现过（数学里极少用小写 o 作变量），
硬设一个反而可能把生僻汉字误判成字母。

## 4. 修复实现

### 4.1 新模块

`system/rag/text_cleanup.py`：

- `fix_pdf_glyphs(text)` —— 修字形（映射 + 删噪声）
- `strip_latex(text)` —— LaTeX 降级为纯文本数学
- `clean_text(text)` —— 两者串联
- `glyph_stats(text)` / `has_glyph_issues(text)` —— 统计与检测，供日志和自检

### 4.2 三处接线

| 位置 | 作用 |
|---|---|
| `scripts/ingest_content.py::_ingest_one_file` | **入库前**修复（治本）。日志与导入汇总都会报修复处数 |
| `system/rag/rag_retrieval_engine.py` 的 `rank_pool` | 证据兜底：覆盖尚未重建的旧库 / 外部内容包 |
| `student_app/gui_app/views/ask_question_view.py::_sanitize_streamed_answer` | 显示兜底：流式 token 直写控件，只能生成结束后整体替换 |

摄取侧的效果（数学必修一，单本）：

```
原始 187,760 字符，待修复 12,300 处（61 种字形 + 噪声 867）
主要：狓×3432、狔×1097、犪×890、犃×585、犳×513、犫×422
修复后残留：0 处
```

### 4.3 两条硬约束

**(a) `clean_text` 必须先 `strip_latex` 再 `fix_pdf_glyphs`。**
模型写的 `\Delta狓` 里 `\Delta` 是命令、`狓` 是被错映射的字母。顺序反了会得到 `\Deltax`
—— 反斜杠命令被粘成一个不存在的命令名，比原来更难看。已用测试锁定
（`test_delta_adjacent_to_glyph_is_not_glued`）。

**(b) 常用汉字必须逐字白名单，不能按码段范围删。**
`状犍犒烈燃犀犁犊犬犯犹狐狗狠` 与错映射字母同处 U+7280–U+72E0、U+70C0–U+70CF 等码段，
其中 **U+71C3 = 燃**、**U+70C8 = 烈**。用范围替换会把「燃烧」「烈火」一起删掉。
测试 `test_real_chinese_characters_are_not_touched` 锁定。

## 5. 顺带修掉的第二个"乱码"：GUI 渲染不了 LaTeX

主人贴的那段里，`\[` `\lim` `\frac` 会以反斜杠**原样显示** —— 因为答案框是
`CTkTextbox`，纯文本控件，不渲染 LaTeX。这是"乱码"的另一半。

处理两条线：

1. **提示词**：`qwen_handler.py` 的 system_prompt 新增第 6 条 ——
   要求变量直接写字母、`√ × ≤ ≥ ≠ Δ` 用 Unicode、分式写 `(Δy)/(Δx)`，
   **禁止** LaTeX 标记；第 7 条要求沿用材料中的符号写法。
2. **输出侧兜底**：`strip_latex()` 把没拦住的标记降级。

降级示例：

| 输入 | 输出 |
|---|---|
| `\frac{\Delta y}{\Delta x}` | `(Δy)/(Δx)` |
| `\lim_{\Delta x \to 0}` | `lim(Δx → 0)` |
| `\sqrt{3}` | `√(3)` |
| `$x_1 + a^{2}$` | `x₁ + a²` |
| `\vec{AB} \cdot \vec{CD}` | `AB→ · CD→` |
| `\alpha \in (0, \pi/2)` | `α ∈ (0, π/2)` |

不认识的命令只去掉反斜杠保留名字（`\foo{bar}` → `foo{bar}`），**不吞内容**。

## 6. 生成链路核查：大模型确实参与了

主人提出「希望问答环节有大模型的参与」。核查结论是**它已经在参与**，三条证据：

1. **教材原文与内容 JSON 里都没有 LaTeX。** 主人贴的 `\lim_{\Delta狓 \to 0} \frac{...}`
   只可能是生成模型写的。内容 JSON（`science_grade_10_auto.json`）里既没有「导数」
   也没有这些乱码字符 —— 排除了"预置答案直出"的可能。
2. **代码链路**：`main_window._eager_init_all_models()` 构造 `ModelHandler(...)`
   并以 `llm_handler=` 传入 `RAGRetrievalEngine`；引擎在 `elif self.llm:` 分支里
   `llm_used = True` 并逐 token 流式输出。模型未加载时答案会带
   `⚠️ 大模型未加载…` 前缀，**不会静默降级成纯检索**。
3. **实测**（问题：导数的定义是什么？）：

```
[模型加载] 2.5s  模型可用 = True
[llm_used] True
[置信度] 0.9375
[路由集合] ['neb_math_grade_11', 'neb_math_grade_10']
[证据书目] ['math_elective_2', 'math_elective_2', 'math_elective_2']
答案：…在点x处的导数f'(x)定义为： f'(x) = lim(h → 0) (f(x+h) - f(x))/(h) …
[检查] 答案中错映射字符 = 0，噪声 = 0；含反斜杠 = False；证据中错映射字符 = 0
```

证据三条全部来自**数学选择性必修第二册**（导数正是这一册的内容），路由正确。

## 7. 本轮额外修掉的两个真缺陷

### 7.1 评测脚本会把报错的负样本算成正样本（严重）

`scripts/eval_rag.py` 在单题抛异常时，兜底行写死了 `"is_negative": False`：

```python
rows.append({"id": item["id"], ..., "is_negative": False, "error": str(e)})
```

后果：**报错的负样本被重新分类为正样本**。某一轮 78 题里 35 题报错，样本显示成
「正 71 / 负 7」，而 `Recall@10 = 100%` 是在**仅 36 题有值**的基础上算出来的。

修复：
- 兜底行保留该题原有的 `type / register / cross_grade / is_negative`；
- 汇总新增 `n_error / n_valid`，报告里显式打印
  `⚠️ N 题评测异常，下方指标仅基于 M 题 —— 不可用于结论`。

**现在任何一次带报错的评测都无法再"看起来很好"。**

### 7.2 稠密检索降级链会让整个问答崩掉

HNSW 段会**间歇性**失败（`Error finding id`），且连 `col.get()` 都可能一起失败。
原实现里内存精确检索兜底抛异常时会一路冒出去，导致**整个 query 中断**
—— 评测里一度 78 题挂掉 35 题。

改为逐级降级，且**任何一级都不允许抛异常**：

1. 不带 `where` 重查一次（过滤下推本身可能是失败源），父块在 Python 侧剔除；
2. 内存内精确余弦检索；
3. 都失败则返回空列表 → 上层走「零证据拒答」，**用户看得到**，不会是错误答案。

实测：一次运行里命中降级，无过滤重查取回 14 条，78/78 全部成功。
新增 2 项回归测试（45/45 通过）。

## 9. 遗留

1. **`chapter` / `section` / `page` 元数据仍为空** —— 溯源只到"书名 + 年级"，到不了页码。需 PDF 结构解析。
2. **PDF 版式还原不在范围内**：根号 `槡` 被替换成 `√`，但抽取顺序是"被开方数在前、根号在后"
   （`２槡２` = 2√2），分数也在抽取时丢掉了分数线（`Δ狔Δ狓`）。要到"公式完整可读"还需版式重建。
3. **`\bar{x}`（均值）降级为 `x`** —— 重音符号丢失。组合字符在 CTkTextbox 里渲染不可靠，暂不处理。
4. **抽取质量本身**：本次只修了"字符映射"，没有解决"公式结构"。若主人希望答案里的公式
   像书上那样排版（分数线、上下标位置），需要另做 PDF 版式解析或接公式识别。
