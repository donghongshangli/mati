# 人工导入教材的适配情况说明

> 日期：2026-10-01
> 结论一句话：**支持，但只适配了「RAG 检索」这一半；「内容浏览/做题」这一半必须另外生成，且扫描件会被静默丢弃。**

---

## 1. 两条导入通路（能力差别很大，别混为一谈）

主菜单 → **🧑‍🏫 教师工作台** → 里面有两个分区，走的是**两条互不相通**的链路。

| | 分区 1「导入教材到知识库」 | 分区 2「从 PDF 生成章节与测试题」 |
|---|---|---|
| 代码 | `student_app/gui_app/views/teacher_view.py:166-208` | 同文件 `:213-258` |
| 输入 | 文件选择器（`*.pdf *.txt *.md`） | 单个 PDF |
| 做什么 | 复制到 `textbooks/` → `ingest_directory()` → 向量库 | 调 `tools/pdf_to_content.py::generate_from_pdf()` → Qwen 生成 content JSON |
| 产出 | **RAG 可问答** | **可浏览章节 + 做题** |
| 学科/年级 | ❌ **没有选择器** | ✅ 有下拉框（`:98-104`），显式传参 |
| 耗时 | 秒级～分钟 | 数分钟（要跑大模型） |

> **关键差异**：分区 2 显式带了 `subject` / `grade`，生成的内容不受文件名影响；
> 分区 1 **完全没有学科/年级输入**，元数据只能靠文件名推断。

## 2. 已适配的方面（实测）

### 2.1 支持的文件格式

| 扩展名 | 处理方式 |
|--------|---------|
| `.pdf` | PyMuPDF 直接抽文本（`extract_text_from_pdf`） |
| `.txt` / `.md` | 直读 UTF-8 |
| `.jsonl` | 直读 |
| `.json` | 递归扁平化为 `key: value` 行（`_extract_json_text`） |

### 2.2 字段映射（每条 chunk 写入 ChromaDB 的元数据）

| 字段 | 说明 | 来源 |
|------|------|------|
| `source` / `source_file` | 原始文件名 | 文件系统 |
| `type` | 固定 `neb_curriculum` | 常量 |
| `subject` | 规范学科，如 `science` / `math` / `chinese` | 解析 |
| `grade` | 年级编码 `10`/`11`/`12`，失败为 `unknown` | 解析 |
| `grade_span` | 适用年级区间，如 `11,12` | 教材目录表 |
| `grade_label` | 中文标签，如 `高一` | 教材目录表 |
| `discipline` | 细分学科，如 `physics` / `chemistry` | 教材目录表 |
| `book_id` / `book_title` / `book_volume` | 教材标识与书名 | 教材目录表 |
| `publisher` / `edition` | 出版社 / 版次 | 教材目录表 |
| `catalog_matched` | 是否命中教材目录表 | 解析 |
| `content_type` | 目前恒为 `body`（预留） | 常量 |
| `chunk_index` | 块序号 | 分块 |
| `content_sha256` | 抽取文本的哈希（预留增量判重） | 抽取 |
| `source_key` | 文件名哈希前 10 位，参与 ID 生成 | 文件名 |

### 2.3 学科判定（四级回退）

1. `mati_data/config/textbook_catalog.yaml` **书名精确匹配**（当前 27 本）
2. 中文学科关键词（物理/化学/生物/科学 → science；数学 → math；信息技术 → computer_science…）
3. 英文关键词（physics / chemistry / science / math / computer…）
4. ASCII 前缀兜底，清洗后为空则落 `general`

### 2.4 年级判定（三级回退）

1. 教材目录表（27 本，依据已联网核实）
2. **路径**：`textbooks/grade_10/xxx.pdf`、`class_3/`、目录名裸数字（`textbooks/10/`）
3. 文件名中的 1–12 数字（自动排除 4 位年份，如 2019 / 2025）

> ⚠️ 第 2 条是**本轮刚补回**的：P0 改造期一度只看文件名而丢掉路径，与 `HOW_TO_PROCESS.md`
> 承诺的「年级从文件夹名提取」不符。已修复并加回归测试（`tests/test_curriculum_catalog.py`）。

### 2.5 其他

- **集合归属**：`neb_{subject}_grade_{n}`；无年级时为 `neb_{subject}`。集合 metadata 同步写入 `subject` / `grade` / `hnsw:space=cosine`。
- **幂等**：同一文件名重复导入会先删旧块再写新块（ID 为 `集合:文件名哈希:序号`）。
- **分块**：512 字符 / 10% 重叠；中文句末标点（`。！？；`）正确断句；公式与代码块为保护区。
- **溯源**：`result["sources"]` 返回完整元数据（书名、出版社、版次），**但界面尚未展示**，见 §3.4。

## 3. 未适配 / 有硬限制的地方

### 3.1 扫描件与图片型 PDF 会被**静默丢弃**（最严重）

链路：`detect_pdf_type` 前 3 页文字 < 100 字符 → 判为 `"scanned"` → 走 OCR 分支，而：

| 环节 | 实际状态 |
|------|---------|
| 判断依据 | `ingest_content.py::detect_pdf_type`：前 3 页合计 <100 字符即判 scanned |
| EasyOCR | `self.easyocr_reader` 恒为 `None`（初始化代码位于 `_ensure_client` 的 `return` 之后，**不可达**）|
| Tesseract 包 | 已装 → `TESSERACT_AVAILABLE = True` |
| Tesseract 二进制 | **不在 PATH** → 实测 `TesseractNotFoundError` |
| 语言参数 | 写死 `lang='eng'`，**没有中文包 chi_sim** |
| 最终结果 | 返回 `""` → 0 块 → 控制台 `logger.error`，**界面上仍显示「✅ 导入完成」** |

**实测复现**：造一个前 3 页各 1 个字符的 PDF 混在 6 个文件里一起导入，
结果 `neb_science` 共 213 块 = 自编讲义(211) + 文本笔记(2)，**扫描件贡献 0 块且无任何界面提示**。

> 影响：老师导入一整本扫描版教辅，界面说成功，实际学生一条都问不到。

### 3.2 教师端导入没有学科/年级选择 → 元数据靠猜

分区 1 的界面里没有下拉框，文件又被**平铺复制**到 `textbooks/` 根目录（不建 `grade_10/` 子目录），
所以 §2.4 的第 2 条（按目录判年级）在这条通路上**天然用不上**。

实测（沙箱导入 6 个文件）：

| 文件 | 判定 source | 判定 grade | 落到的集合 |
|------|-----------|-----------|-----------|
| `2025人教版物理必修一.pdf` | science | 10 | `neb_science_grade_10` ✅ 目录命中 |
| `自编化学补充材料.pdf`（在 `grade_11/` 下）| science | 11 | `neb_science_grade_11` ✅ 路径命中 |
| `science_grade_12_manual.json` | science | 12 | `neb_science_grade_12` ✅ 文件名数字 |
| `王老师自编物理讲义.pdf` | science | **unknown** | `neb_science` ⚠️ |
| `生物笔记.txt` | science | **unknown** | `neb_science` ⚠️ |
| `扫描版物理教材.pdf` | science | unknown | （0 块，见 §3.1）|

**由此暴露一个曾导致人工教材"隐身"的 bug（本轮已修）**：
`_get_relevant_collections` 原先在年级精确匹配命中时**只返回有年级的集合**，
把 `neb_science`（无年级）排除在外；而 GUI 默认就带年级（`current_grade_filter = "10"`），
于是**所有年级推断失败的人工教材在学生提问时完全检索不到**，且没有任何提示。

> 修复：无年级集合按定义覆盖全部年级，一律常驻候选集。
> 回归测试：`tests/test_collection_routing.py`（5 项）。

### 3.3 学科粒度只有 5 档，物理/化学/生物不分家

关键词表把 **物理 / 化学 / 生物 / 科学** 统一映射到 `science`。因此：

- 导入一本**生物**书 → 会进 `neb_science_grade_10`，与物理书**混在同一个集合**
- `discipline`（physics / chemistry / biology）虽然写进了 metadata，但**集合路由与 GUI 学科过滤器都不区分**
- GUI 学科下拉只有：科学 / 数学 / 语文 / 英语语法 / 计算机科学 / 社会科学

> 影响：学生问"光合作用"（生物）时，命中的证据里可能混入物理块；反之亦然。

### 3.4 溯源信息做了但没显示

`ask_question_view.finalize_answer(..., source_info=...)` 有完整的「来源：xxx」渲染逻辑
（`views/ask_question_view.py:210-223`），但 `main_window.py:819` 调用时**没有传 `source_info`**。

结果是：检索层辛苦算出的 `sources`（含 `book_title`、`publisher`、`page`）**一次都没有展示给用户**。
对"可追溯"这个目标来说，等于白做。

### 3.5 导入 PDF ≠ 能在「浏览学科」里看到

- 分区 1 只写向量库，**不生成 content JSON** → 不会出现在「浏览学科 / 章节 / 做题」里
- 分区 2 才会生成 content JSON，但要跑 Qwen，数分钟
- 也可以手写 content JSON，但 schema 很严：

```json
{ "subject": "Science", "grade": 10, "topics": [
    { "name": "第一章 …", "subtopics": [
        { "name": "…", "concepts": [
            { "name": "…", "summary": "…", "steps": ["…"],
              "questions": [ { "question": "…", "acceptable_answers": ["…"], "hints": ["…"] } ] }
        ] } ] } ] }
```

约束（`system/data_manager/content_manager.py:94-125`）：

- **必填** `subject`（非空 string）、`grade`（1–12 整数或 `"1"`–`"12"` 字符串）、`topics`（数组）
- `topics[].name` 与 `topics[].subtopics` 必填
- 顶层与 topic 层均 `additionalProperties: false` → **多写一个字段整个文件加载失败**
- 失败时只 `logger.error` 后 `continue` —— **学科会静默消失，界面无提示**

文件放置规则：`content/` 下**扁平的 `*.json`**，或 `content/{subject}/content.json`。

### 3.6 其它

| 项 | 情况 |
|---|---|
| 章节/页码元数据 | `chapter` / `section` / `page` 字段已预留但**填默认值**，PDF 不做结构解析 → 无法按章节过滤或定位 |
| 内容去重 | 同名文件重导会替换；**改名的同一本书会重复入库**（`content_sha256` 已写入但未用于判重）|
| 年级推断失败 | 落 `neb_{subject}`，不影响检索（已修），但年级软加权失效 |
| 学科推断失败 | 落 `neb_general`，**不参与任何学科路由**，等价于没导入 |
| `notes/` 目录 | 已从默认摄取范围移除（该目录当前只有项目文档，非教学内容）；需要时用 `--input notes` 显式指定 |

## 4. 未做适配时的实际影响（按严重度排序）

| # | 情形 | 后果 | 可观测性 |
|---|------|------|---------|
| 1 | 导入扫描件 / 图片型 PDF | 0 块入库 | ❌ 界面显示「✅ 导入完成」 |
| 2 | 文件名不含学科关键词（如用纯中文短语命名）| 落 `neb_general`，不参与路由，检索不到 | ❌ 无提示 |
| 3 | 年级推断失败 | 原会静默隐身（**已修**）；现仅软加权失效 | 低 |
| 4 | 想把书加进「浏览学科」 | 光导入 PDF 做不到，需另走生成或手写 JSON | ⚠️ 无引导 |
| 5 | content JSON 多写字段 | 整个文件被跳过，该学科消失 | ❌ 仅后台日志 |
| 6 | 期望答案标注书名页码 | 检索层有、界面没显示 | ❌ 无提示 |

## 6. 复现方式

```bash
# 依赖：完整环境（含 chromadb / sentence-transformers / torch）
PY="C:/Users/duanhongshangli/Anaconda3/envs/autoresearch/python.exe"

# 手工导入（命令行等价于教师端分区 1）
$PY scripts/ingest_content.py --input textbooks

# 查看结果落到了哪些集合
$PY scripts/rebuild_index.py --help      # 重建时自带自检汇总
$PY scripts/check_retrieval.py --no-llm  # 集合发现 + 学科路由 + 召回验证

# 回归测试
$PY tests/test_curriculum_catalog.py     # 12 项（含目录判年级）
$PY tests/test_collection_routing.py     # 5 项（含无年级集合不被排除）
$PY tests/test_rag_p0_fixes.py           # 23 项（纯逻辑，WindowsApps python 亦可）
```
