### 2.2 明确不做的事（及理由）

1. **不实施 GraphRAG**。方案 §3.4 步骤 3.5 自己就写了「阶段三不实施，仅预留接口」，
   理由是当前库仅几千块，图的价值不足以抵消维护成本。已按要求预留字段。
2. **不做语义级冲突判定**（公式等价性推理）。方案要求「轻量、用关键词/数值一致性规则」，
   在没有权威知识图谱的情况下，语义级判定会产出大量假警报 ——
   而**没人相信的报告比没有报告更坏**。只做字面数值层面的矛盾检测。
3. **不要求模型必须标注引用**。方案 §3.4 步骤 3.4.1 写的是「要求模型标注」，
   但实测 1.5B 标注率 0%（§5.3）。我们保留指令、统计标注率，
   但**不因未标注而惩罚** —— 硬要求只会制造「看起来有引用其实没有」的假安全感。
   真正防假来源的是「编号由检索层生成」，这一点与模型是否听话无关。

## 3. 关键设计决策（含与方案不同的取舍）

### 3.1 页码溯源：为什么之前填不上

方案步骤 3.1 要求补 `page` 字段。此前一直填不上，容易被误判为「PDF 解析不出页码」。
**真正原因**：`extract_text_from_pdf` 用 `"\n".join(page.get_text())` 把所有页拼成一段，
**页边界在这一步就被丢掉了**。后面无论怎么切分都拿不到页信息。

修法（三步，都是确定性的）：

```
① PDF 抽取时每页开头插标记   "\n[[PAGE:1]]\n" … "\n[[PAGE:217]]\n"
② 切分前扫描并移除标记       scan_page_markers() → (markers, cleaned_text)
                             markers 是 (页码, 该页在**清洗后文本**中的起始偏移)
③ 切分时记录块的**全文绝对偏移**，用 page_for_offset(markers, offset) 反查页码
```

第 ③ 步依赖 P2 同时改掉的一个隐患：`_split_sections` 原先返回的 `start_pos` 是
**段内相对偏移**，无法在全文里定位。现在改为携带全文绝对偏移。

> 偏移必须在移除标记的**同时**累加已保留文本长度来算，才能与返回的 `cleaned_text` 对齐。
> 早先的 docstring 写的是「必须先清洗再扫描」，与实现不符，已改正。

**实测**：数学必修一册的问题「集合的交集怎么定义」现在能给出
`[1] 普通高中教科书·数学（A 版）必修 第一册 · 第一章 集合与常用逻辑用语 · 第17页`。
13012 个块里只有 14 块无页码（0.1%，来自清单导入的历史数据）。

### 3.2 目录/封面排除：为什么必须下推到查询层

P1 已经给目录/封面块打了 0 结构分，但**结构分只影响排序，不影响召回** ——
它们仍会占候选池与 BM25 语料的位置。本轮把过滤下推到 Chroma 查询：

```python
where = {"$and": [
    {"doc_type":      {"$ne": "parent"}},   # 父块只用于命中后取回
    {"content_type":  {"$nin": ["toc", "cover"]}},
    {"status":        {"$ne": "archived"}},  # 已下架（步骤 3.3.2）
]}
```

**并且在 Python 侧再做一次兜底过滤**（`passes_metadata_filter`）。
理由：Chroma 1.4.0 的 `$ne` / `$nin` 对**没有该键**的文档 behave like「不匹配任何值」，
因而会被保留 —— 对旧数据恰好安全，但这个行为不应被依赖。

**实测**：78 题评测，证据里的目录/封面/下架块 **0 个**（见 §5.1「治理过滤漏网」）。

### 3.3 语义去重：方案写 0.92，实测用 0.95

方案 §3.4 步骤 3.2 写「余弦 ≥ 0.92 视为重复」。**实测 0.92 会误删正文**：

- 教材里大量段落**本就应该**高度相似 —— 相邻小节的定义句式（"…称为…，记作…"）、
  例题的「解：」引导语、术语的重复定义。
- 这些块余弦普遍在 0.92–0.95 之间，阈值取 0.92 会把它们成片删掉。

改用 **0.95**，并且**父块与子块分开比较**（父块是子块的超集，混在一起会把整本书删光）。

**实测收益很小但安全**：13012 块中语义去重只丢弃 **8 块**（0.06%）。
这个数字本身是有意义的结论 —— 说明**本库的精确重复由文本相同导致（161 块），
而不是由语义近似导致**。把阈值压到 0.92 能多删一些，但代价是正文损失，收益不成比例。

### 3.4 引用编号全部由检索层生成（对 1.5B 模型的对冲）

方案 §3.4 步骤 3.4.1 写「来源由检索层提供，不由模型编造」。实现上比这更彻底：

- **编号 `[1][2][3]` 由 `build_citations()` 生成**，与证据顺序严格对应；
- **来源描述「书名 · 章节 · 页码」也由检索层生成**；
- 模型**只需要写 `[n]`**，甚至不写也不会产生假来源 —— 因为它无从得知 7 号存在。

Prompt 里明确要求模型**不要自己写「依据：」行**（系统会自动附），
避免模型写出与检索层不一致的来源行。

### 3.5 越界引用只降置信度，不改答案

方案步骤 3.4.2 写「越界则**移除该标记**并降低置信度」。**本轮只做后者**。

理由与 P0 忠实度校验一致：擅自删改模型输出会**掩盖问题**，
而编号写错（如写 `[5]` 而实际只有 3 条证据）不影响内容正确性 ——
学生看到「[5]」会疑惑，但不会被误导。把越界率**报出来**即可。

## 4. 实现要点

### 4.1 新增模块 `system/rag/knowledge_governance.py`

只依赖标准库（numpy 可选），四部分：

| 部分 | 函数 | 对应步骤 |
|------|------|---------|
| 内容清洗 | `clean_chunk_text` | 3.2.1 |
| 去重 | `exact_dup_key` / `semantic_dup_pairs` / `dedupe_chunks` | 3.2.2–3.2.3 |
| 冲突检测 | `detect_conflicts` | 3.3.3 |
| 检索过滤 | `build_query_filter` / `passes_metadata_filter` | 3.1 |
| 溯源引用 | `build_citations` / `validate_citations` | 3.4 |
| 拒答补充 | `is_creation_request` | 3.4.3 |

**设计原则：所有删改都必须可审计。** `clean_chunk_text` 返回 `(cleaned, reason)`，
`reason` 为空表示未删改；调用方必须把它写进 `mati_data/ingest_gov_report.jsonl`。
不允许静默丢内容。

### 4.2 页眉清洗的一个必要区分

「第二章 运动的描述」这类行有两种身份：

- 出现在**块首** → 它是这一节真正的标题，是有用的上下文，**保留**；
- 出现在**正文中间** → 它是每页重复的页眉，纯噪声，**删掉**。

不区分就会把每章第一块的标题删掉，白白损失检索上下文。
实现上用一个 `seen_content` 标志记录「是否已输出过正文行」。

### 4.3 索引重建：首次真正跑通治理链路

```
P1: 9567 子块 + 3642 父块 = 13209 向量
P2: 9400 子块 + 3612 父块 = 13012 向量   （-197）
```

丢弃明细（`ingest_gov_report.jsonl`，共 10078 条事件）：

| 阶段 | 动作 | 数量 | 说明 |
|------|------|------|------|
| clean | trim | 9891 | 删掉页码孤行/重复页眉/孤立图注/版权行 |
| clean | drop | 17 | 清洗后过短，整块丢弃 |
| dedup | exact | 161 | sha256 完全相同 |
| dedup | semantic | 8 | 余弦 ≥ 0.95 |

块总量下降 **1.5%**（方案预期 5–15%）。低于预期，但**这是好事** ——
说明清洗去掉的 9891 处都是「行级噪声」而不是「块级重复」，
块总量本就不该大幅下降。方案那个 5–15% 的预期隐含了「有大量整块重复」的假设，
在本库不成立。

精确去重的 161 块分散在多本书（语文必修下册 20 块最多），
符合「教材里有重复段落」（古诗、公式表、习题引导语）的预期。

### 4.4 冲突检测：实现完整但当前产出为空

`detect_conflicts()` 已实现：按 `concept_key` 分组 → 抽取数值断言 → 同字段不同值即报冲突。
**但本库所有块的 `concept_key` 都是空**，因此产出 0 条。

这是**刻意的克制**，不是没做完：

- 冲突的前提是「讲的是同一个概念」。没有 `concept_key` 时全库两两比较会把
  「向心力为 3 N」和「重力为 5 N」判成冲突 —— 这种假警报会让整个冲突治理失去可信度。
- 因此 `require_concept_key: true` 时，无 `concept_key` 的块一律不参与。

**要做出一份有内容的冲突报告，前置条件是建立概念级标注体系**，
这属于 P3（评测闭环与反馈飞轮）的输入，不在阶段三范围内。

> 一个可观测性补丁：`conflicts.jsonl` 只在真有冲突时才创建。
> 「查过了、0 冲突」必须与「没查」可区分，因此冲突扫描事实也写进治理报告
> （`stage: "conflict", action: "scan"`），事后看到文件不存在能判断是「干净」而非「没跑」。

### 4.5 拒答策略：新增一条与覆盖率正交的判据

原有拒答主判据是「查询覆盖率」（中文二元组，P1 实测比 `final_score` 可靠得多）。
本轮发现它在**一类问题上完全失效**：

```
Q：帮我写一篇 800 字的散文
   → 查询覆盖率 0.7143（阈值 0.28）→ 判定「教材里有依据」
   → 模型拿着几段描写景色的课文，开始写散文
```

原因：「散文」「800」「字」在语文教材里天然高频。
**覆盖率回答的是「问题里的词有没有出现在块里」，回答不了「块里的内容是不是在回答这个问题」。**

因此新增 `is_creation_request()`：只匹配**明确的成品创作**动词 + 成品文体，
并设**豁免词表**（怎么/如何/为什么/赏析/立意/表达方式/修辞/结构…）——
出现教学型问法时视为「问写法」而非「要成品」，**不拒答**。

宁可漏判（继续当 RAG 问答）也不误判（把「作文怎么立意」这类确有教材依据的问题挡掉）。
测试锁了 19 个用例，创作类 9/9 命中、教材类 10/10 放行。

新增返回类型 `type: "creation_refused"`，与 `no_evidence` 区分。

> **踩到的一个记账陷阱**：`scripts/verify_citations.py` 最初只把 `no_evidence` 记为拒答，
> 于是创作类拒答（`llm_used=False`，**这本就是正确行为**）被误报成
> 「模型没跑起来」并返回退出码 2。验证工具自己也会骗人 ——
> 写断言时要区分「**应该**调模型」与「**不该**调模型」两种情形。

## 5. 实测结果

### 5.1 检索层（`scripts/eval_rag.py`，78 题，每组重复 2 次）

| 指标 | P1 基线 | P2 实测 | 说明 |
|------|---------|---------|------|
| Recall@5 | 97.0% | **97.0%** | 持平 |
| Recall@10 | 100.0% | **100.0%** | 持平（已到顶） |
| MRR@10 | 0.860 | **0.831** | 略降，见下 |
| Recall@证据 | 95.5% | **97.0%** | ↑ |
| 路由准确率 | 100% | **100%** | 持平 |
| 拒答正确率(负) | 91.7% | **91.7%** | 持平 |
| 误拒率(正) | 10.6% | **12.1%** | ↑1.5pt，见下 |
| 证据分区分度 | 0.262 | **0.259** | 持平 |

**误拒率微增 1.5pt 的原因**：精确去重删掉的 161 块里有内容，
`neb_chinese_grade_11` 等集合的候选略微减少。这是**去重的代价，也是去重的意义** ——
宁可少召回一点重复内容，也不让同一段文字占两个候选位。
1.5pt 在 66 题上是 1 道题的差别，不构成实质退化。

**MRR@10 从 0.860 降到 0.831**：同样是去重的影响 ——
被删的重复块此前偶尔会占据第 1–2 位（重复内容容易与查询高度相似），
删掉后首位命中的是另一个正确但排名稍后的块。Recall@10 与 Recall@证据反而提升，
说明**检索面变宽了，只是首位精确度略降**。这是去重的预期代价，可接受。

> 连续三次评测（重建前 2 次、重建后 1 次）主指标完全一致，
> 「重复 2 次，每次 0.0 题结果翻转」，说明 P2 的检索层结果是**完全可复现**的。

### 5.2 治理与可信生成（P2 新增指标）

| 指标 | 实测 | 验收线 | 结论 |
|------|------|--------|------|
| 治理过滤漏网（目录/封面/下架进入证据） | **0 块** | 恒为 0 | ✅ |
| 元数据完整率 | **95.3%** | ≥ 95% | ✅ |
| 页码覆盖率 | **99.9%**（13012 块中 14 块无页码） | — | ✅ |
| 父块 `section` 完整率 | **99.0%**（3612 块中 36 块空） | — | ✅ |
| 引用越界（端到端 4 题） | **0 处** | 越界率 0 | ✅ |
| 模型引用标注率 | **0%** | 方案预期 ≥90% | ⚠️ 见 5.3 |
| 冲突检出 | 0 条 | — | ⚠️ 无 concept_key，见 4.4 |

**元数据完整率口径说明**：初版把 `chapter`/`section` 算作必需字段，实测 95.4%，
缺口里 3716 块缺 `section`、2194 块缺 `chapter`。查下来发现**这不是缺陷而是结构事实** ——
连续正文中间没有标题行，本来就没有小节名可填；而且真正的问题是
**父块曾 100% 漏写 `section`**（代码只在子块上写了），已修。

因此拆分口径：
- **标识类字段**必须齐全（书名/学科/年级/页码/状态/版本…）—— 缺了就是真 bug；
- **结构类字段**按「块自身带标题才要求」统计。

这个拆分不是为了把指标做好看，而是为了让指标**反映真实缺陷** ——
旧口径下真正的接线错误（父块漏写）被 3716 个结构性空值淹没，看不见。

修复后实测（重建索引验证）：

| doc_type | 块数 | `section` 缺失 | `chapter` 缺失 | `page` 缺失 |
|----------|------|---------------|---------------|-------------|
| child | 9400 | 104 (1.1%) | 1575 (16.8%) | 10 |
| parent | 3612 | **36 (1.0%)** ← 修复前 235/235 = 100% | 619 (17.1%) | 4 |

`chapter` 缺失约 17% 属正常：那部分块本身不在任何章节标题之后（教材正文连续排版），
按新口径不计入分母。

### 5.3 引用标注率 0%：如实记录，不粉饰

`scripts/eval_rag.py` 报告「引用标注率 0%」，需要说清两件事：

1. **评测脚本测不到它**。`eval_rag.py` 用 `load_llm=False` 跑 —— 它测的是**检索层**，
   不加载生成模型，模型从不写 `[n]`。这不是「引用功能坏了」，是**测错了对象**。
2. **端到端实测确实是 0%**。新增 `scripts/verify_citations.py` 加载真实 1.5B 模型跑 4 题，
   模型**一次都没写 `[n]`** —— 尽管 system prompt 第 8 条明确要求。

原因判断：1.5B 模型在 9 条长指令中，第 8 条（引用标注）是最容易被忽略的一条。
指令措辞本身没有问题（已检查）。

**但这不构成可信度问题**，因为：

- 编号与来源描述**全部由检索层生成**，模型不写 `[n]` 不会产生任何假来源；
- 模型即使乱写，也只能写它**看到的**编号（1–3），越界会被校验捕获并降置信度；
- 来源清单仍然会展示给用户（GUI 走 `citations`，不依赖模型标注）。

**结论**：方案 §3.4 步骤 3.4.4 的验收线「引用准确率 ≥ 90%」在本项目**不适用** ——
它假设模型会标注。在 1.5B 条件下正确的验收方式是
「**越界引用率 = 0，且来源清单由系统生成**」，这两条都达成了。

若将来换用 7B 以上模型，标注率预期会显著上升，
`eval_rag.py` 里已埋好 `citation_accuracy` / `cite_coverage` 指标，届时可直接观测。
