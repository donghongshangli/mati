## 1. P0-1 导入结果校验

### 问题
`ingest_directory` 无返回值，`_ingest_one_file` 静默 `return 0`。扫描件被丢弃时，
控制台只有一行 `logger.error`，而教师端界面照样打印「✅ 导入完成」。

### 修复方式

**`ingest_content.py`**
1. `_ingest_one_file` 改为返回结构化结果 dict：
   `{file, path, status(ok|skipped|error), chunks, collection, subject, discipline, grade, grade_label, book_title, catalog_matched, reason}`
2. `ingest_directory` 汇总为：
   `{input, found, ok, skipped, failed, chunks, files[]}`，且当 `found > 0 且 ok == 0` 时打 ERROR 日志
3. 新增 `OCREngineUnavailable` 异常，让「读不出来」与「没有内容」可区分
4. 新增 `format_ingest_summary()`：逐文件渲染状态/块数/集合，并对跳过与失败逐条给出原因；
   `ok == 0` 时明确输出「没有任何文件成功入库 —— 不要把它当作「导入完成」」
5. CLI 新增 `format_ingest_summary` 输出，且全部失败时 `exit(2)`

**`rebuild_index.py`**：复用同一汇总；`ok == 0` 时返回码 2；自检表新增 discipline 列

**`teacher_view.py`**：新增 `import_result_box` 明细框 + `_set_import_result()`，
按 `ok/skipped/failed` 三分支给出 ✅ / ⚠️ / ❌ 结论（不再是无条件「导入完成」）

### 影响范围
- 新增字段但不改既有语义：所有调用 `ingest_directory` 的地方（CLI、rebuild、教师端）都已同步
- 返回值从 `None` 变为 dict —— 外部脚本若依赖 `None` 需注意（仓库内无此类调用）
- **行为变化**：导入失败不再"看起来成功"，教师端会出现明确的 ⚠️ / ❌

## 2. P0-2 教师端导入加学科/年级下拉

### 问题
教师端分区 1「导入教材到知识库」没有学科/年级输入，文件被平铺复制到 `textbooks/` 根目录，
元数据只能靠文件名猜 —— 自编讲义一律落 `neb_science`（无年级）。

### 修复方式

**`ingest_content.py`**
1. `UniversalContentIngester.__init__` 新增 `force_subject` / `force_grade`
2. 学科经 `RetrievalConfig.canonical_subject` 归一化；若是细分学科（物理/化学/生物），
   同时锁定 `force_discipline`，使集合落到 `neb_physics_*` 而非家族级 `neb_science_*`
3. 非法年级（如 99）被忽略并告警，不写入
4. `extract_metadata` 优先级变为：**强制指定 > 教材目录表 > 路径/文件名启发式**
5. CLI（`ingest_content.py`）与 `rebuild_index.py` 新增 `--subject` / `--grade`

**`teacher_view.py`**
- 分区 1 新增「学科」「年级」两个下拉，默认均为**自动识别**
- 学科可选到细分：自动识别 / 科学（不细分）/ 物理 / 化学 / 生物 / 数学 / 语文 / 英语语法 / 计算机科学 / 社会科学
- 年级可选：自动识别 / 高一 / 高二 / 高三 / 初一 / 初二 / 初三

### 影响范围
- 默认值「自动识别」→ 不改动既有行为的默认路径
- 教师端多两个控件，`textbooks/` 仍是平铺写入（若要按年级分目录组织，路径判年级仍有效）
- 影响所有走 `UniversalContentIngester` 的入口（CLI / rebuild / 教师端）

## 3. P1-3 接通溯源展示

### 问题
`ask_question_view.finalize_answer(source_info=...)` 有完整的「来源：xxx」渲染逻辑，
但 `main_window.py` 调用时**从不传该参数**。检索层算好的书名/出版社/年级一次都没显示过。

### 修复方式
**`main_window.py`**
1. 新增模块级 `_format_sources(sources, limit=2)`：
   - 按 `book_title`（回退 `source` / `source_file`）去重
   - 渲染为 `书名（年级）`，多本用「；」连接，超过 limit 显示「等 N 本」
   - 顺序即证据排序（第一条最相关）
2. 查询返回后取出 `response['sources']` → `source_info`，传入 `finalize_answer`

### 影响范围
- 只影响「提问」界面的显示：现在会多一行「来源：普通高中教科书·物理 必修 第二册（高一）」
- 不改动检索与生成逻辑；`finalize_answer` 签名不变（`source_info` 本就是可选参数）
- 依赖 P0 阶段写入的 `book_title` / `grade_label` 元数据（未命中教材目录的文件回退显示文件名）

## 4. P1-4 扫描件明确处置

### 问题
1. `detect_pdf_type` 取**前 3 页**文字总量与阈值 100 比较 → 封面+目录页的书会被**误判为扫描件**（整本丢弃）
2. 扫描分支把「`import pytesseract` 成功」当作「OCR 可用」，实际 tesseract 可执行文件不在 PATH，必然抛异常后返回 `""`
3. Tesseract 调用写死 `lang='eng'`，**没有中文包**

### 修复方式
**`ingest_content.py`**
1. `detect_pdf_type` 改为**等距抽 6 页取每页文字数的中位数**（中位数对封面/插图页不敏感），
   中位数 < 80 才判为扫描件
2. 新增 `_ocr_status()`（带缓存）真实探测能力：
   - `pytesseract` 可 import **且** `get_languages()` 能跑通，才算 tesseract 可用
   - 记录已安装语言包，缺 `chi_sim` 时单独告警
3. 新增 `_extract_with_ocr()`：无可用引擎时抛 `OCREngineUnavailable`，消息里带具体原因
4. `extract_text_with_tesseract` 按实际语言包动态选 `chi_sim+eng`，缺中文包时退回 `eng` 并明确告警
5. 清掉 `_ensure_client` 里 `return` 之后的死代码（EasyOCR 初始化原本永远不可达）

### 影响范围
- **文本型 PDF 不受影响**（27 本教材中位数 380–860 字符，远高于 80）
- **封面页多的书不再被误判**，减少整本丢失
- **扫描件现在会如实报「跳过 + 原因」**，而不是 0 块 + 界面成功
- 若将来装了 tesseract + chi_sim，扫描件会自动走 OCR（无需改代码）
- EasyOCR 仍未安装（`requirements.txt` 无此依赖），但分支不再崩溃

## 5. P2-5 学科细分到 discipline

### 问题
关键词表把 物理/化学/生物 统一映射为 `science`，三科共用一个集合 `neb_science_grade_10`，
学生问「光合作用」可能召回物理块。

### 修复方式

**配置层**
1. `textbook_catalog.yaml` 新增 `discipline_split_subjects: [science]` —— 只对含多个细分学科的家族拆集合，
   math / chinese / english / computer_science / social_studies 名字保持不变（避免无谓重建）
2. `retrieval.yaml` 新增：
   - `discipline_aliases`：物理/physics → physics 等
   - `discipline_to_subject`：physics → science（反查家族，供旧集合名回退）

**`curriculum_catalog.py`**
3. `collection_name_for(subject, grade, discipline, split_subjects)` —— 拆分时用 discipline 作为集合键
4. `CurriculumCatalog` 加载 `discipline_split_subjects`

**`retrieval_config.py`**
5. 新增 `canonical_discipline()`、`subject_for_collection()`；`canonical_subject()` 支持细分名反查家族

**`rag_retrieval_engine.py`**
6. `_discover_collections` 读取集合 `discipline` metadata；名字回退时用 `discipline_to_subject` 反查家族
   （否则按 `Science` 提问会匹配不到 `neb_physics_grade_10`）
7. `_get_relevant_collections(subject, grade, discipline)` 新增可选收窄：给了 discipline 只查该科，
   没有对应集合则退回家族（不返回空）
8. `query(..., discipline=None)` 贯通

**`subject_selector.py` / `main_window.py`**
9. 顶栏学科选择器新增 物理 / 化学 / 生物 / 语文；`current_discipline_filter` 由选项推导
   （「科学」→ None 检索全家族；「物理」→ physics）
10. 「浏览学科」进入时清空 discipline 过滤，避免残留

### 影响范围
- **需要重建索引**（集合名变更，HNSW 不支持原地改）：已完成，11 个集合 / 6066 块
- **学生端「科学」入口不受影响**：`_get_relevant_collections("Science")` 仍返回物理+化学+生物全部集合
  （已加回归测试 `test_family_subject_returns_all_disciplines`）
- 顶层学科过滤器从 5 项变为 9 项；多出的 物理/化学/生物 是**收窄**，不是替代
- 无生物教材，故 `neb_biology_*` 尚未产生；`discipline=生物` 会退回家族检索（已测试）
- 旧索引已备份：`chroma_db_backup_old_embedding`（本次重建前）、`chroma_db_backup_pre_p0`（P0 之前）

## 6. P2-6 content JSON 容错与报错

### 问题
各层 schema 均为 `additionalProperties: False`，content JSON 多写一个键
（哪怕只是备注）就整份文件校验失败并被 `continue` 跳过 —— 用户看到的现象是
**「这个学科在界面上凭空消失」**，只有后台日志留一行 error。

### 修复方式

**`content_manager.py`**
1. 新增 `sanitize_content()`：校验前按 schema 白名单**递归剔除非定义字段**
   （顶层 / topics / subtopics / concepts / questions 五层），带深度保护（`_MAX_SUBTOPIC_DEPTH=6`）防畸形数据爆栈
2. 新增 `_dropped_keys()`：记录被剔除的键路径，用于提示教师修复
3. 新增 `load_errors` 列表 + `get_load_errors()` / `_record_load_issue()`：
   - `warn`：已自动忽略未知字段（含键名列表）
   - `error`：文件加载失败，附原因，**明确写出「该学科不会出现」**
4. 扁平 `.json` 与 `{subject}/content.json` 两条加载路径都接入

**`main_window.py`**
5. 新增 `_warn_content_load_issues()`：启动后延迟 800ms 弹一次警告框列出失败文件与原因；
   `warn` 级别只写日志不打扰用户

### 影响范围
- **容错不放水**：必填字段缺失、类型错误、年级越界仍照常报错
  （已加测试 `test_missing_required_field_still_fails`、`test_wrong_type_still_fails`）
- `sanitize_content` 返回副本，不就地修改原始 dict（已测试）
- 传入的 content 会**少掉** schema 未定义的字段 —— 若某些扩展字段被其他模块读取，需先登记进 schema
- 新增启动时可能的警告弹窗（仅在真的有文件加载失败时出现）

## 7. 顺带修掉的 3 个新发现缺陷

| # | 缺陷 | 发现方式 | 修复 |
|---|------|---------|------|
| 1 | **目录名里任意数字被当年级**：`_p1_probe` 里的 `1` 被判成「一年级」，整批教材被错标 | 沙箱导入验证时发现 | 目录必须**恰好全数字**才算年级（`c.isdigit()`）；加回归测试 `test_path_directories_with_incidental_digits_are_not_grades` |
| 2 | **README 被当教材入库**：`textbooks/README.md` → `neb_readme` 集合（7 块） | 重建后自检看到多余集合 | `ingest_content.py` 新增 `SKIP_FILENAMES`，发现阶段排除 README；已删除该集合 |
| 3 | **强制「生物」落到家族集合**：`force_subject="生物"` 只设了 subject，discipline 退化为 science | P0-2 验证时发现 | 强制学科时同时解析并锁定 `discipline`，落到 `neb_biology_grade_11` |
