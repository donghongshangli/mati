### 2.2 明确不做的事（及理由）

1. **不用本地 Qwen 做子问题拆解**。方案原文提到"用小模型生成 2–3 个子查询"，
   但本地 1.5B + CPU 上一次生成需 3–10 秒，与方案 §1.2 自己定的
   「交互式问答额外延迟上限 1.5–2 s」硬约束直接冲突。
   本轮先用**确定性规则**（连接词 + 疑问尾缀）拆解，零延迟、可解释、可回归；
   模型兜底留作后续可选开关。
2. **不引入 cross-encoder 精排**（`bge-reranker-base`）。方案里本就把标为「默认关闭」，理由是
   +1.1 GB 内存与 0–800 ms 延迟风险。当前库仅 1.3 万向量，特征加权重排已够用。
3. **不改 GraphRAG**（方案 §3.5 明确阶段三不做）。

### 2.3 新增的一个范围外修复（必须做）

实施中发现**年级硬过滤与项目文档声明的「年级只做软加权」自相矛盾**，

## 4. 实现要点

### 4.1 混合检索与 RRF

- **双路**：稠密向量路（每集合 20 条）+ BM25 关键词路（每集合 20 条）。
- **融合用 RRF（k=60）**，不用「分数归一化后加权求和」：
  多路分数尺度不可比（余弦落在 [-1,1] 且分布集中，BM25 是无界正数且长尾），
  而 RRF 只依赖排名。P0 已经踩过一次同类坑（来源权重污染阈值）。
- **改写变体作为独立一路**参与 RRF，不需要人为给各变体分配权重。
- **BM25 语料**按集合惰性构建并缓存（keys 含条数，索引重建后自动失效）。

### 4.2 7 特征重排

```
final = w_sim*余弦相似度       (0.40)
      + w_bm25*BM25分(批内归一) (0.20)
      + w_term*词元覆盖率       (0.15)
      + w_struct*结构信号       (0.10)   # 定义/定理/例题 > 目录/封面
      + w_source*来源优先级     (0.05)   # 由 0.15 进一步压低
      + w_version*教材版本      (0.05)
      + w_grade*年级亲和        (0.05)   # 保留 P0 的 F3 修复
```

方案 §3.3 给的是 6 特征表（无年级亲和）。这里**多保留一个 `grade_affinity`**：
P0 刚修好它的死分支，直接删掉属于功能回归；因此把 `similarity` 从 0.45 降到 0.40 配平。

### 4.3 父子索引

- **子块（~384 字符）用于召回**：向量表达集中，相似度更高；
- **父块（~1000 字符完整小节）用于生成**：定理陈述、例题题干与解析不会被拆散；
- 元数据用 `doc_type: child|parent` 区分，子块带 `parent_id`；
- 稠密召回用 `where={"doc_type": {"$ne": "parent"}}` 排除父块
  （实测 `$ne` 会**保留**缺该键的旧数据，因此对历史数据安全）；
- 命中多个子块指向同一父块时**只保留一份**，避免重复内容吃掉预算；
- 父块缺失时保留子块原文 —— 宁可给半截证据，也不凭空丢证据。

### 4.4 拒答判据换成查询覆盖率（本轮最重要的一条工程结论）

**加权总分不能当拒答/相关性判据。** 它含多项常量特征
（来源 0.05 + 结构 0.10 + 版本 0.05 + 年级 0.05 ≈ 0.2 下限），
且 BM25 用的是**批内最大值归一化**（每批必有一个候选拿满分）。

实测（旧索引）：

| | 加权总分 |
|---|---|
| 库外问题（负样本）最高 | **0.78** |
| 教材内问题（正样本）最低 | **0.46** |

**完全不可分** —— 拿它拒答必然失效（实测拒答正确率仅 25%）。

改用 `query_coverage`：**中文二元组**（近似词边界）覆盖率，
是**绝对量**（不随同批候选变化），才具备可标定的物理含义。

> 教训：**用于排序的分 ≠ 用于判定的分**。排序可以是相对量，判定必须是绝对量。

并且覆盖率按「原句 + 各改写变体」**取最大值**：学生用口语提问
（"摩尔浓度怎么算来着"）时原句与教材措辞不重合，但同义变体（"物质的量浓度"）会重合。
只算原句会把这类问题误判为无依据 —— 这正是 Query 改写在本轮的**主要收益来源**。

### 4.5 年级软过滤路由

`routing.grade_mode: soft`（默认）：同家族**全部年级**的集合都参与召回，
年级只决定①集合排序②重排的 `grade_affinity`。
配套**同年级收窄规则**：同年级候选 ≥2 条时丢弃跨年级候选；
不足时才扩展 —— 让「跨年级能兜住」与「同年级更精准」同时成立。

### 5.1 逐组件解读（每个组件的贡献互不重叠）

**A → B：BM25 混合检索（+RRF）**

- 误拒率 **24.2% → 18.2%**；证据分区分度 **0.200 → 0.258（+29%）**。

- **Recall 没有提升**，这需要诚实说明：本轮的**父子索引同时上线**，
  子块变小（512 → 384 字符）后稠密召回本身已经足够好（A 组已 93.9%），
  因此 BM25 的召回增益在这套评测集上被"顶掉"了。
  BM25 的真实价值体现在**证据质量**：它让「该拒答的更像该拒答
  （分区度 +29%）、不该拒答的更少被误拒（−6pt）」。
- MRR 略降（0.992 → 0.980）：BM25 会引入一些字面匹配但语义一般的候选，
  把个别更好的结果挤到第 2 位 —— 这是混合检索的固有代价，量级可接受。

**B → C：Query 改写（同义扩展 + 子问题拆解）**

- 误拒率 **18.2% → 12.1%（−6.1pt）**，这是本轮改写的**主要收益来源**。
- 机制：拒答判据的查询覆盖率**按「原句 + 变体」取最大值**。
  学生用口语提问（"摩尔浓度怎么算来着"）时原句与教材措辞不重合，
  但同义变体（"物质的量浓度"）会重合 —— 只算原句会把这类问题系统性误判为无依据。
- Recall 无变化：变体只增加检索路，而 top-10 在 B 组已经饱和。
- 结论：**改写在本项目里的定位是"降低误拒"，不是"提升召回"** ——
  这与方案原始预期（提升 Recall@10）不同，属于实测修正了预期。

**C → D：年级软过滤路由**

- 路由准确率 **93.9% → 100%**；跨年级 Recall@10 **0% → 100%**；
  整体 Recall@10 → **100%**；书面题 92.9% → 100%。
- 代价明确可见：MRR **0.972 → 0.852**。软过滤让同家族全部年级参与召回，
  高一/高二内容相互竞争，头部排序纯度下降。
- 取舍判断：本系统的问法是"教材里怎么讲"，**召回覆盖比头部纯度更重要**
  （宁可第 3 条才给对，也不要"查不到"）；且证据分区分度基本持平（0.259 → 0.254）。
  因此取 D。若产品更看重首条命中，把 `routing.grade_mode` 改回 `hard` 即可。

### 5.2 拒答阈值的标定（数据驱动，不是拍脑袋）

`refuse_below_query_coverage` 的取值来自评测集扫描（D 组）：

| 阈值 | 拒答正确率（负样本被挡） | 误拒率（正样本被误挡） |
|------|:---:|:---:|
| 0.15 | 41.7% | 1.5% |
| 0.20 | 66.7% | 1.5% |
| 0.25 | 75.0% | 6.1% |
| **0.28（当前取值，F1 最优）** | **91.7%** | **10.6%** |
| 0.35 | 91.7% | 21.2% |
| 0.50 | 91.7% | 36.4% |

取 **0.28**（F1 = 0.905）。教育场景下幻觉代价高于拒答，故不取"最低误拒"的 0.20
（那样 4/12 个负样本会漏过）。若产品更看重"不误拒"，改 0.22 即可。

### 6.1 两项未达标指标的诚实说明

**① 证据保留率 34.1% —— 是指标定义与配置不匹配，不是系统问题。**

方案 §5.1 把它定义为「送入模型的证据 token / 召回的总 token」。
但"召回的总 token"取的是**精排池**，而精排池大小由 `rerank_k=10` 决定（固定 10 条），
证据预算却只有 2000 token、父块约 1000 token ——
**在 rerank_k=10 的设定下，保留率的结构性上限就是约 20~35%**，
除非把精排池裁到与预算同量级（rerank_k≈2，代价是失去选择余地）。

真正影响答案质量的量是**预算利用率**：实测 **82.6%**（入选 token / 预算），
即证据窗口基本用满。因此本轮**并列报告两个指标**：

- 证据保留率（入选/精排池）：34.1% —— 说明精排池里大部分候选不会进模型（正常）
- 证据预算利用率（入选/预算）：82.6% —— 说明给模型的证据窗口被有效使用

**② 误拒率 10.6% —— 差 0.6pt，且已给出可切换的工作点。**

10.6% 略高于标的 ≤ 0.10。实测误拒的样本几乎全是**口语化提问**
（"摩尔浓度怎么算来着"、"引力常数大概是多大来着"），
它们的措辞与教材差异大，覆盖率偏低但稠密相似度其实很高（0.64–0.75）。

三个可选工作点：

| 工作点 | 拒答正确率 | 误拒率 | 适用 |
|--------|:---:|:---:|------|
| `0.20` | 66.7% | **1.5%** | 最怕误拒（学生被拒答体验差） |
| `0.25` | 75.0% | 6.1% | 折中 |
| **`0.28`（当前）** | **91.7%** | 10.6% | 最怕幻觉（教育场景默认） |

**③ 置信度区分度显示为 0.000 —— 评测未加载生成模型所致，不是回归。**

评测模式（`load_llm=False`）下没有生成答案，`confidence` 恒为 0，
因此脚本**并列输出无需模型即可测的「证据分区分度」：0.254（≥0.15 ✅）**。
真实置信度区分度已在 P0 阶段用大模型端到端验证过（0.40–1.00 的真实分布，原为恒定 0.3）。

## 7. 本轮发现并修复的真问题

### 7.1 `neb_chemistry_grade_10` 的 HNSW 段静默失效

现象：4 道化学题的稠密检索整体返回空，日志报
`Error creating hnsw segment reader: Nothing found on disk`。

**被掩盖的原因**：BM25 走 `col.get()`、不走 HNSW，因此混合检索模式下
这个问题**基本不可见** —— 只有纯稠密模式（消融 A 组）才暴露。
这正是"多路检索会掩盖单路故障"的实例：**收益与盲区同时到来**。

修复：`rebuild_index.py` 自检新增**逐集合向量试查**；
并新增 `scripts/verify_index.py` 做多轮校验 + 记录重写修复。

### 7.2 年级硬过滤导致假拒答（与文档声明矛盾）

现象：`静电场中场强的定义式是什么？`（物理必修三，目录标**高一**）
在 GUI 选「高二」时被判「教材中未找到」—— 而知识库里确实收录了这本书。

根因：`_get_relevant_collections` 在年级精确命中时**只返回该年级的集合**，
与项目文档明确写的「年级只做软加权与集合排序，不做硬过滤」自相矛盾。
本项目年级口径本就存在校际分歧（物理必修三征订标高一、实际多在高二上），
硬过滤等于**把口径差异变成"查不到"**，且用户完全无法从界面看出原因。

修复：改为软过滤 + 同年级收窄（§4.5），并补 5 项回归测试。

### 7.3 Chroma 的两个「静默零召回」陷阱 + 三道防线（重要，已写入项目记忆）

**(a) 同一进程内不能对同一路径创建第二个 `PersistentClient`。**
实测 100% 复现：先建客户端 c1 读元数据、再建 c2 查询，
c2 会有 1–2 个集合间歇性报 `Error finding id` / `Nothing found on disk`（磁盘文件完好）。
已修 3 处：`eval_rag.py`、`check_retrieval.py`、`rebuild_index.print_summary`，
并给 `RAGRetrievalEngine` 增加 `chroma_client` 注入参数。

> 这个坑最初表现为**评测结果随机波动**（同一配置 Recall@10 在 65%~94% 之间跳）。
> 如果不是坚持追查，P1 的全部指标都会被当成"看起来变好了"的噪声。

**(b) 刚重建完的索引可能未完整落盘。**
重建进程退出时个别集合的 HNSW 仍是半成品（实测某集合的 `data_level0.bin`
只覆盖前约 100 条、`index_metadata.pickle` 为 0 字节），该集合会整体静默零召回。
Chroma 在后续进程打开时会自愈 —— 但**只有被访问过才会**。
因此重建后必须跑一次健康校验；`rebuild_index.py` 已自动调用，未通过返回码 3。

**(c) 最终解法：给"HNSW 不可用"加内存精确检索兜底。**
三条防线叠加，把"静默零召回"这一最危险的失效模式彻底消除：

| 防线 | 位置 | 作用 |
|------|------|------|
| 重试（3 次、退避递增） | `with_retry` | 覆盖"内存重建需要一点时间"的窗口 |
| **内存精确余弦检索兜底** | `_brute_force_route` | HNSW 彻底不可用时改用全量扫描 |
| 健康校验 + 自动修复 | `verify_index.py` | 重建后主动发现并按需重写集合 |

兜底为什么可行：本库仅 1.3 万向量 × 512 维 = 27 MB，
一次全量余弦扫描只要几毫秒，**结果确定且无近似误差**，
比和一个有落盘缺陷的近似索引较劲更可靠。且 `col.get()` 走 sqlite、**不经过 HNSW**，
因此在 HNSW 失效时它依然可用（BM25 语料也是靠这一点在故障时照常工作）。

**(d) 评测侧：默认重复运行取均值 + 报告稳定性。**
`--repeat N`（默认 2）对每组配置重复运行并取均值，同时输出**逐题翻转数**：
翻转数为 0 才说明结论稳定。本次最终报告用 `--repeat 3`，四组翻转数均为 **0**。

### 7.4 关于评测稳定性的准确表述（不要过度声称）

修完上述问题后仍有一处**残余波动**，如实记录：

| 指标 | 实测稳定性 |
|------|-----------|
| **Recall@10（默认混合配置）** | **完全稳定** —— 4 次独立运行均为 100.0% |
| 误拒率（默认混合配置） | 单次运行 5.7% / 10.6% / 10.0% / 10.6%（约 ±2~3pt） |
| Recall@10（纯稠密消融模式） | 3 次运行 92.0% / 93.9% / 93.9%（约 ±1 题） |

**结论**：主指标（Recall@10）可稳定复现；**在拒答阈值附近有 1~3 题的抖动**
（覆盖率恰好落在 0.28 边界的题会翻）。因此：

- 报告采用**多次运行的均值**（文中 10.6% 为 3 次均值），不引用单次数字；
- 阈值类结论要看**标定表整条曲线**（§5.2），不要盯单点；
- 残余波动的根因仍是 Chroma 近似索引的惰性加载，属环境特性，
  已由重试 + 内存精确检索兜底限制在"个别题"量级，未影响主结论。

### 7.5 其它修复

| 问题 | 说明 |

### 7.6 评测集自身的标注错误（自查发现）

用索引内 `$contains` 硬证据审计后修正 4 题：

| 题 | 原标注 | 实际所在 | 依据 |
